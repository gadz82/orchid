## What this demonstrates

The basketball demo is Orchid's "hello world". It wires two chat-facing `GenericAgent` instances — an NBA stats expert and a sports psychologist — using built-in tools implemented as `OrchidTool` subclasses in the example's Python package, plus the PostgreSQL storage backend provided by the `orchid-storage-postgres` plugin. A third agent, `trivia_generator`, is activated by the example's Pollen + Bloom schedule to produce a weekday morning trivia digest. No MCP servers, no external APIs, and no custom agent classes are required — the agent definitions live in `agents.yaml`.

## Run it

```bash
git clone https://github.com/gadz82/orchid-examples
cd orchid-examples/basketball
cp .env.example .env
docker compose up --build
```

This starts the API (`http://localhost:8080`), the web UI (`http://localhost:3000`), PostgreSQL, Qdrant, and the MCP gateway. Ollama runs on your host with `llama3.2` and `nomic-embed-text` (plus `minicpm-v` for document uploads).

## What to look for

- `storage.class: orchid_storage_postgres.OrchidPostgresChatStorage` → the `orchid-storage-postgres` plugin provides chat persistence; any importable `OrchidChatStorage` subclass can be plugged in here, and the framework resolves it via dotted import at startup.
- `tools.<name>.class` → built-in tools are `OrchidTool` subclasses referenced by dotted path; plain Python functions referenced with `handler:` are also supported.
- `skills.player_performance_review.steps` → a cross-agent skill chains two agents in sequence; the supervisor executes each step in order and passes context forward.
- `events.schedules` + `events.triggers` → a weekday cron schedule activates the event-driven `trivia_generator` agent. See [Pollen + Bloom](/concepts/pollen-bloom).
- `defaults.rag.enabled: false` → RAG is disabled globally; individual agents can override this per-field.
- `auth.dev_bypass: true` → skips identity resolution for local development; remove this in production.
