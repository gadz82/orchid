# orchid-website/ — Orchid Documentation Site

## Purpose

Static documentation website for the Orchid multi-agent AI framework. Generated with `next build` (`output: 'export'`), deployable to any static host. **Not** an application — no API routes, no server at runtime.

## Non-purpose

- Not a demo or consumer of the Orchid Python/TypeScript packages.
- Does not import `orchid_ai`, `orchid_api`, or any sibling package directly.
- Does not run agents or call orchid-api.

## Stack

- **Next.js 15** (App Router, `output: 'export'`), React 19, TypeScript strict.
- **Tailwind CSS v4** with `@theme inline` in `src/app/globals.css`.
- **MDX** via `@next/mdx` (configuration) + `next-mdx-remote/rsc` (content rendering).
- **gray-matter** for frontmatter parsing.
- **Shiki** for build-time syntax highlighting (`src/lib/shiki.ts`, custom theme `src/lib/shiki-orchid-theme.json`).
- **Inter** via `next/font/google`.
- **Vitest** + `@testing-library/react` for component tests.

## Dev / Build / Test commands

```bash
cd orchid-website
npm install
npm run dev         # http://localhost:3000 (Turbopack)
npm run build       # pre-checks nav then runs next build
npm run lint           # eslint
npm test               # vitest run (headless)
npm run test:watch     # vitest interactive
npm run extract:schema # regenerate src/data/config-schema.json from the Pydantic schema
```

### Regenerating the configuration schema

`src/data/config-schema.json` is generated from the Pydantic models in `orchid_ai.config.schema`
and the YAML-to-env mapping in `orchid_ai.config.yaml_env`.  Re-run whenever either source changes:

```bash
cd orchid-website

# Using the orchid virtualenv (recommended):
../../orchid/.venv/bin/python scripts/extract_config_schema.py --out src/data/config-schema.json

# Or via the npm script (uses whatever `python` is on PATH):
npm run extract:schema
```

The extractor walks `OrchidAgentsConfig` recursively for `agents.yaml` fields and reads
`YAML_TO_ENV` for `orchid.yml` fields.  Both the script and the generated JSON must be
committed together.  Best-practice notes live in `src/data/config-best-practices.json`
and are maintained by hand — re-running the extractor does not overwrite them.

## Content: where it lives and the frontmatter contract

All prose content lives in `src/content/**/*.mdx`. The catch-all route at
`src/app/[...slug]/page.tsx` maps URL slugs to content files:

- `/concepts/rag` → `src/content/concepts/rag.mdx`
- `/examples` → `src/content/examples/index.mdx`
- `/quickstart` → `src/content/quickstart.mdx`

**Every MDX file must start with this frontmatter:**

```yaml
---
title: "Page Title"
description: "One-sentence description used in <meta> and on-page subheading."
package: orchid          # orchid | orchid-api | orchid-cli | orchid-mcp | orchid-frontend | cross-cutting
section: concepts        # home | ecosystem | quickstart | concepts | packages | configuration | examples | meta
order: 30                # controls sidebar sort within a group
tags: []
sources: []              # relative paths to source files used to author this page
related: []              # hrefs to related pages
example: ""              # href to a companion example (e.g. "/examples/restaurant")
external: []             # external links [{label, url}]
---
```

Bodies are empty in Phase 1. Do **not** add prose until Phase 2+.

## `<CodeBlock>` API

```tsx
import CodeBlock from '@/components/CodeBlock';

<CodeBlock
  tabs={[
    { language: 'python', label: 'Python', code: 'x = 1' },
    { language: 'bash', label: 'Shell', code: 'pip install orchid-ai' },
  ]}
  filename="example.py"   // optional: shows header strip above tabs
  showLineNumbers         // optional
  highlight="{1,3-5}"     // optional: highlight ranges (future)
  wrap                    // optional: wrap long lines
/>
```

Valid languages: `python | bash | yaml | typescript | json | http | tsx | text`.

In MDX, any fenced code block is automatically wrapped into a single-tab `<CodeBlock>` via the `pre` component override in `MdxPre.tsx`. No special syntax needed.

### Adding a new language

1. Add the language key to the `CodeTab['language']` union in `CodeBlock.tsx`.
2. Add it to `SUPPORTED_LANGS` in `src/lib/shiki.ts`.
3. Verify the Shiki grammar is in the `shiki` bundle (most common languages are).

## Navigation

`src/nav.ts` is the single source of truth for the IA. Adding or removing a route requires:

1. Adding/removing the `NavNode` entry in `navNodes`.
2. Creating/deleting the corresponding MDX file in `src/content/`.
3. `npm run build` will fail if nav and content are out of sync (via `scripts/check-nav.ts`).

## `siteConfig` and placeholders rule

All references to the repo URL, contact email, and license must go through `siteConfig` in `src/site-config.ts`. The values are currently `PLACEHOLDER…` and must remain so until explicitly updated. Do not inline URLs or email addresses elsewhere.

## Citation rule (concept and package pages)

When writing concept or package pages (Phase 2+), every non-obvious claim must be citable to a source file. List the source paths in the `sources: []` frontmatter field. Do not assert implementation details that can't be verified by reading the listed files.

## Brand-name prohibition

**A specific integrator brand name is forbidden from appearing anywhere in committed files inside `orchid-website/`.** The exact term is defined in the root `CLAUDE.md`; run `grep -ri <term> orchid-website/` before declaring any task done.

This applies to code, comments, docstrings, env-var names, README prose, test fixtures, and this file. Use generic terms instead (`acme.example.com`, `mytenant.example`, `INTEGRATOR_CLIENT_ID`, …). Platform-specific work for that integrator belongs in the consumer directory at the monorepo root (outside `orchid-website/`).

## Common mistakes

- **Nesting `<button>` inside `<button>`.** Causes React hydration errors.
- **Using `output: 'export'` with server-only features.** No API routes, no `getServerSideProps`, no cookies at runtime.
- **Missing `generateStaticParams`.** The `[...slug]` route has `dynamicParams = false`; if a path is not in `generateStaticParams`, it will 404 at build time.
- **Tailwind v3 syntax.** This project uses Tailwind v4 — no `tailwind.config.js`, use `@theme inline` in CSS.
- **Importing `lucide-react` icons not present in the installed version.** Pin icon names to those in the `lucide-react` version listed in `package.json`.
